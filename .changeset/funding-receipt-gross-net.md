Funding receipt: define `amount` as the gross the sender paid and make `amount` and `currency` optional, so a receipt can omit them when only the received amount is known; add optional `netAmount` / `netCurrency` for what the recipient received; add an optional `type` (donation, match, grant) saying what the payment is; add an optional `via` naming the intermediary that facilitated or processed the payment; state that a receipt may be updated in place, e.g. to add or remove `from`, and what that does and does not hide; give `paymentRail` an open `knownValues` vocabulary; define `paymentNetwork` as where `transactionId` can be looked up (CAIP-2 chain ID for onchain payments); add privacy guidance to `transactionId`; and state how to record payments that pass through platforms, hosts, or regrantors. Existing receipts remain valid. Readers can no longer assume `amount` or `currency` is present: the generated types are now `amount?: string` and `currency?: string`.
